织 UI

给工作台用的界面体系：先告诉人现在要做什么。

原则与规范

给使用这套体系的人看的规则：什么时候用什么颜色、字号、版式。

织 UI 是给工作型产品用的界面体系：老师每天看的工作台、管理员的配置后台、学生的练习客户端、运营的数据看板。它要让用户打开页面三秒内知道“现在要我做什么”，然后少点几下把事做完。第一个使用它的产品是跨境电商客服实训平台；以后的新产品换一组品牌色就能直接用。

五条原则

  1. 先回答“现在要我做什么”。 工作台首屏第一块是待办（ActionItems），统计和图表往后放。设置页先给结论（“系统运行正常，1 项需要处理”），再给明细。
  2. 颜色都有含义。 brand 只给主操作和选中态；红（danger）表示出错、逾期、不及格；橙（warning）表示快到期、多日未操作；分类色（cat-1…cat-6）只表示类别。其他一律是 ink 系列和 line 系列的中性色。不出现装饰性的颜色。
  3. 数字是主角。 能用一个数字说清的事就给一个大数字（figure-xl、figure），别用一段话。每行、每块只突出一个数字或一条进度。
  4. 空的时候也要设计。 仪表盘、数字条、图表没数据时照常画出骨架：数字用浅灰“—”或浅灰 0，图表用斜纹或虚线占位，中间一张提示卡说清还差什么；不要把整块收成一句话。列表没数据时用 EmptyState，说清这里会出现什么、怎么开始。
  5. 改版式先出稿。 新页面、整页改版、换视觉方向，先做一个可以直接打开的 HTML 对比稿：问题诊断 → 改前截图 → 改后画面 → 空状态，示例数据按真实规模编。确认后再写代码。

文案

  • 写给使用者看，用他们的说法：说“学生在练习”，不说“会话 active”；说“买家等了 6 分钟”，不说“idleSeconds 360”。
  • 按钮以动词开头，说清点了会发生什么：“下发任务”“导入学生”“立即备份”。不写“确定”“提交”。
  • 提示条先写结论，再写一句原因或下一步：“定时备份没有按时执行。最近一次在 7 月 23 日。”
  • 错误说清哪里错、怎么改：“达标线请填 0–100 之间的整数”。不道歉，不写“操作失败”。
  • 时间写成人话：“还剩 1 天”“已逾期 2 天”“今天 14:20”“3 天前”。
  • 不用 emoji，不用感叹号，不把技术名词（ID、token、JSON）放到普通用户的页面上。
  • 中文和数字、英文之间不加空格的地方保持一致：数字和单位之间加空格（“45 人”“6 分钟”），百分号不加（“93%”）。

颜色

两套主题：light（默认）和 dark，每个颜色令牌都有两个值。

  • 底色：工作台页面用 canvas（浅灰），上面放 surface（白）的内容板。设置页、登录页、弹窗直接用 surface。表头、分组标题用 surface-2；可点击行的悬停和选中用 surface-hover。
  • 线：line 用于分隔线和内容板描边；line-strong 用于输入框和次按钮的边框。
  • 文字：ink 正文和标题；ink-2 次要说明；ink-3 表头、时间戳、计数；ink-disabled 只用于禁用态。三者在 canvas、surface、surface-2 上都 ≥4.5:1。
  • 品牌：brand 实底配 on-brand 文字；浅底 brand-soft 上的文字用 brand-ink；正文链接是 link（= brand-ink）。一屏只给一个 brand 实底的主按钮。
  • 状态：info、success、warning、danger，各有 -soft 浅底。状态色必须配文字或图标，不能只靠颜色区分。删除确认按钮用 danger 实底配 on-danger。
  • 分类：cat-1…cat-6 和对应 -soft，用于图表系列、业务环节、分组。在跨境客服里：售前沟通 cat-2（青绿）、售中处理 cat-1（蓝）、售后处理 cat-3、客户分层维护 cat-4。
  • 焦点：所有可操作元素在键盘聚焦时显示 2px focus 实线，外扩 2px。

给新产品换品牌色

每个产品只改 brand、brand-hover、brand-soft、brand-ink、on-brand 和 cat-1（与品牌同色）这六个令牌的两套值，其他不动。换色后检查三组对比度：on-brand 在 brand 上 ≥4.5:1，brand-ink 在 surface 和 brand-soft 上 ≥4.5:1，brand 在 surface 和 canvas 上 ≥3:1（作为进度条和焦点环）。默认品牌色是蓝色（#1d5fd1），常见、稳重，和红、橙两种状态色都分得开；中性色是略带蓝的冷灰，和品牌色同一色调。

字体与字号

  • 字族 sans：拉丁字母和数字用 Manrope（字体文件随体系提供，fonts/），中文落到系统字体（Windows 上是微软雅黑，Mac 上是苹方）。不依赖 Google Fonts，学校机房断网也能正常显示。
  • 默认字号 14px（body）。一个页面通常只用到四级：title 页名，heading 内容板标题，body 正文，small/caption 说明。
  • display（28px）一页最多一处：问候语或空状态大标题。
  • 数字一律开启等宽数字（font-variant-numeric: tabular-nums）：figure-xl 用于一页唯一的核心数字，figure 用于数字条，figure-sm 用于表格里的分数和金额。
  • 行宽不超过 40 个汉字左右；长说明放进弹窗或帮助里，不铺在页面上。

间距、圆角、阴影

  • 4px 网格：组件内部 space-1–space-4，组件之间 space-4–space-6，区块之间 space-6–space-8。内容板左右内边距 space-5。
  • 圆角：标签 radius-xs，按钮和输入框 radius-sm，菜单和提示条 radius-md，内容板、弹窗、抽屉 radius-lg，筛选标签、开关、头像 radius-pill。
  • 阴影只有三级：内容板 shadow-board（几乎看不见，靠描边分区）、浮层 shadow-pop、弹窗 shadow-dialog。不要给普通卡片加大阴影。

版式

两种页面骨架，按页面性质选，不要混用：

  • 工作台（每天要用、要做判断的页面：教师端、运营后台、看板）：侧栏 sidebar（240px）+ 顶栏 topbar（56px，页名后面跟页签）+ canvas 底上的内容板（Board）。内容区最大宽度 content-max（1200px）。一页一到三块板：第一块是待办或概况，第二块是主列表，之后才是图表。见“示例页面”。
  • 一张纸（设置、配置、表单为主的页面：管理后台的系统设置、个人设置）：整页 surface 白底，不用内容板；每一节左栏 280px 写这一节是什么，右栏放表单或列表，节与节之间用 line 分隔。

通用规则：

  • 每页只有一个 primary 按钮，放在工具栏右侧或空状态里。
  • 列表行整行可点开详情；行尾只留一个“…”菜单收编辑、删除等操作。
  • 表格列不超过 6–7 个；每行一个视觉重点；数字列右对齐。
  • 新建、编辑用右侧抽屉（字段多）或居中弹窗（字段少于 4 个）；删除一律二次确认。
  • 页面上不放解释性的长句；口径说明进 HelpTip，表单字段的短提示用 Field 的 hint。

仪表盘

工作台首页、报表、看板的上半部分，按这个顺序从上到下：

  1. 待办卡片（ActionItems）：三张并排，回答“现在要我处理什么”。有待办时带红 / 橙，fact 写具体是谁；为 0 时图标块变灰带绿色小勾、数字浅灰，fact 写背景信息（“本周已复核 3 份”“现在没人在接待”）。不写“都处理完了”。
  2. 关键数字卡片（KpiCard，放进 zh-kpis）：3–4 张，每张配一个小图——分数用半圆仪表并刻达标线，比率用圆环，覆盖率用进度条，变化用绿 / 红小胶囊。
  3. 需要关注的名单：上面几格是原因（图标 + 大数字，点一格筛选），下面一张名单，最多显示 5 条，其余放“查看全部”抽屉；这样人多人少这块高度不变，下面的图表不会被压下去。
  4. 图表：分布、能力等。

四条规矩：

  • 没数据也画仪表盘。 卡片、坐标轴、维度名称照常在；数字是浅灰“—”或浅灰 0，小图只画灰色底圈，图表用斜纹或虚线占位，中间一张小提示卡（“还没有评分 · 学生完成接待后出现”）。只有列表才用 EmptyState 一句话 + 按钮。
  • 状态交给图标和颜色，不重复写成文字。 灰 0 + 绿色小勾就是“没事”，红 / 橙大数字就是“要处理”。
  • 口径进问号，事实留页面。 “60 分及以上的比例”“竖线是训前测评”进 HelpTip；“40 人里 37 人及格”“李四让买家等了 6 分钟”留在卡片上。
  • 每张卡只突出一个数。 其他信息用灰色小字放在下面一行。

状态与交互

  • 悬停：可点击的行和菜单项变 surface-hover；次按钮变 surface-hover；主按钮变 brand-hover。
  • 选中：页签下划线 brand；侧栏导航 brand-soft 底 + brand-ink 字；筛选标签 brand-soft 底。
  • 禁用：ink-disabled 文字、surface-2 底，不改变布局。
  • 加载：列表用骨架行，按钮内显示转圈并保持宽度；不用整页遮罩。
  • 动效：只用 120–180ms 的颜色和位移过渡；尊重系统的“减少动态效果”设置。

图标

  • 用 lucide 图标（React 项目装 lucide-react），线宽 1.75，导航和按钮里 16–18px，颜色跟随文字（currentColor）。
  • 图标总是配文字出现；只有含义非常明确的工具栏图标（搜索、关闭、更多）可以单独出现，并写 aria-label。
  • 不用 emoji 做图标或装饰。
  • 体系目前没有自己的标志：产品标志由各产品提供，未提供时显示一个 brand 实底方块里的产品首字（见示例页面侧栏）。

组件

左边可以直接点着试，右边是什么时候用、怎么用。

Button操作

按钮触发一个动作；文字以动词开头，说清楚点了会发生什么（“下发任务”“导入学生”，不写“确定”“提交”）。

  • primary（brand 实底）：一屏最多一个，给这个页面最主要的事。
  • secondary（默认）：其他常规操作。
  • ghost：工具栏里的次要操作（导出、下载模板）。
  • danger：只出现在“确认删除”弹窗里，页面上的删除入口收进“…”菜单。
  • size="sm" 用在表格行内，lg 只用在登录页和空状态。

调用方提供：文字（children）、可选的 16px lucide 图标（icon）、onClick。不要只放图标不放字，除非是工具栏里含义明确的图标按钮并带 aria-label。

Switch操作

开关：立即生效的开/关（启用场景、上架商品、每天自动备份）。开为 brand，关为 line-strong。

调用方提供：checked、onChange、label（读屏名称，必填）。开关旁边要有文字说明它控制什么；需要点“保存”才生效的选项用复选框，不用开关。

Field表单

表单字段：标签在上，输入控件在中间，提示或错误在下。错误出现时替换提示，不同时显示。

调用方提供：label、一个输入控件（Input、Select 或自定义）、可选 hint、error。提示写成一句给人看的话（“留空表示不设截止”），不写字段的技术含义。表单两列排布用 grid，列间距 space-5，行间距 space-4。

Input表单

单行输入框，高 control（36px），边框 line-strong，聚焦时边框变 brand 并加一圈 brand-soft。

调用方提供：原生 input 属性；校验失败时传 invalid，并在外层 Field 写出错误原因。占位符写示例（“例如：…”），不要把说明写进占位符。

Select表单

原生下拉框换了外观，选项不超过十几个时用；更多选项或需要搜索时换成可搜索的选择器。

调用方提供：options（{value,label} 列表）或 <option> 子元素、value、onChange。工具栏里的筛选下拉框宽度 180–220px。

Tabs导航

页签切换同一页面里的几种视图，放在顶栏页名后面；带数量时数量用 ink-3，选中项的数量用 brand-ink，下划线 2px brand。

调用方提供：items（{id,label,count?}）、value、onChange。页签 2–5 个；超过 5 个说明页面该拆了。页签之间是并列视图，不要拿来做步骤。

Segmented导航

分段控件：同一份数据的 2–4 种看法（待复核 / 已复核 / 全部；按周 / 按月），放在内容板标题行或工具栏里。

调用方提供：items、value、onChange。和 Tabs 的区别：Tabs 换页面视图，Segmented 只换当前列表的筛选或口径。

FilterChips导航

筛选标签：按分组或状态快速筛列表，单选，带数量；选中态是 brand-soft 底 + brand-ink 字。

调用方提供：items（第一项一般是“全部”）、value、onChange。“需要关注”这类跨分组的筛选放在最后。标签超过 8 个时改用下拉框。

Tag状态

标签有两种用法，不要混：

  • 状态（tone）：success 完成/达标，warning 快到期/多日未练，danger 逾期/低于及格线，info 进行中，brand 品牌提示，neutral 普通属性。状态标签必须有文字，可加 dot。
  • 分类（cat-1…cat-6）：业务环节、分组等没有好坏的类别。跨境客服里：售前 cat-2、售中 cat-1、售后 cat-3、客户维护 cat-4。

一行里最多一个彩色标签；表格每行都有的属性（如“练习”）用 neutral 或干脆写在第二行文字里。

Avatar状态

头像：有照片用照片（外部提供 <img>），没有就取姓名第一个字，按名字固定一种分类色，同一个人每次颜色都一样。

调用方提供：name、可选 size（sm 24 / md 32 / lg 40）。名单、监控列表、评论里用；不要拿头像当装饰。

Progress状态

进度条：完成人数、完成度。默认 brand；逾期还没完成用 danger，快截止用 warning。上方一行写“33 / 45 人完成”和百分比。

调用方提供：value、total、可选 unit、tone、hideLabel（表格里只要细条时）。

Alert状态

提示条：页面内的提醒，不打断操作。先写结论（加粗的 title），再写一句原因或建议，右侧可放一个操作按钮。

  • danger 出错且影响使用，warning 需要处理但还能用，info 一般告知，success 操作结果（通常用 toast 更合适），brand 产品引导。
  • 一页最多两条；更多时合成一条“有 N 项需要处理”。

调用方提供：tone、title、正文、可选 action。

HelpTip反馈

问号提示：标签、标题旁边一个小问号，鼠标移上去（或键盘聚焦）显示一段说明。

  • 用来收“看一次就记住”的话：这个数怎么算（“60 分及以上的学生占比”）、这一格管什么（“买家发来消息后 3 分钟以上没人回”）、图例（“竖线是训前测评，红色是最弱两项”）。这类话直接铺在页面上会显得信息多、像机器生成的说明书。
  • 不要收随数据变化的事实（“李四让买家等了 6 分钟”“40 人里 37 人及格”）：那是使用者要看的内容，留在页面上。
  • 表单字段下的短提示（“留空表示不设截止”）照常用 Field 的 hint 显示，不改成问号。
  • 浮层挂到 body 上、固定定位，放在有 overflow: hidden 的内容板里也不会被裁掉；离屏幕底部近时自动往上翻。一段说明不超过两行。

调用方提供：children（说明文字）、label（读屏用，默认“说明”）。

Board数据

内容板：工作台页面的基本单位。浅灰 canvas 底上放白色内容板，一页一到三块；板之间 space-4。

  • 标题行 52px：标题用 heading，数量用 ink-3，右侧放 1–2 个次要操作或“全部 →”链接。
  • 里面是列表、表格、数字条时不传 padded（它们自带内边距）；纯文字或表单传 padded。
  • 不要在板里再套板，不要给板加彩色边条。

调用方提供：title、可选 count、extra、padded、内容。

ActionItems数据

待办卡片：工作台首屏的第一块，回答“现在要我处理什么”。三张卡片并排，每张是图标块 + 名称 + 大数字 + 一句事实，整张卡可点，右上角写去处（“去复核 ›”）。

  • 有待办时：danger 用于马上要处理的（低分待复核），warning 用于要留意的（买家在等、快截止）；图标块、数字和卡片描边一起带上颜色。fact 写具体是谁、哪个任务（“其中 1 份低于 60 分（李四 · 货损退款协商）”）。
  • 为 0 时：卡片照常在，图标块变灰并带一个绿色小勾，数字变浅灰。不要写“都处理完了”“没有”——灰 0 已经说明了，重复写显得啰嗦。fact 换成有用的背景：“本周已复核 3 份”“现在没人在接待”“下一个截止：「售后差评挽回」还剩 2 天”。
  • 三项都是 0 也照常摆三张卡片，不要收成一句话：使用者每天看同一张脸，结构不随数据变。
  • 名称旁的口径说明（“买家发来消息后 3 分钟以上没人回”）放进 help，鼠标移上去才看到。

调用方提供：items（icon、label、count、unit、fact、tone、help、action、onAction）。

KpiCard数据

关键数字卡片：报表、看板顶部的 3–4 个核心结果，每个数配一个一眼能读懂的小图。几张卡片放进 zh-kpis 容器里并排，卡片之间 16px。

  • 小图按数的性质选：分数用 gauge（0–100 半圆仪表，mark 刻一道达标线，低于达标线画红）；比率用 ring（圆环）；覆盖率、完成度用 bar（0–1 进度条，如“40 / 45 人”）。一张卡只配一个小图。
  • 变化用 delta：正数是绿色胶囊“↑9”，负数是红色“↓3”，旁边写比的是什么（deltaLabel：“较训前”“较上周”）。
  • 随数据变化的事实放 fact（“40 人里 37 人及格”）；口径说明（“60 分及以上的学生占比”）放 help，进问号浮层，不铺在卡片上。
  • 没有数据时 value 传空：数字显示浅灰“—”，小图只画灰色底圈，不显示 fact 和 delta。卡片结构不变，不要换成一句话。

调用方提供：label、value、unit、delta、deltaLabel、fact、help、chart。

Stats数据

数字条：3–5 个并排的关键数字，用竖线分隔，放在一块内容板里。适合紧凑的位置（班级概况、侧栏）；报表、看板顶部要一眼看出好坏时，用 KpiCard。

  • 没有数据时显示浅灰“—”，不要显示 0（0 是真实的值），也不要写“暂无”。
  • delta 写“+9”“-3”，正数绿、负数红；tone 只在数字本身就是坏消息时用（逾期数）。
  • 口径说明（“60 分及以上”）放 help，进问号浮层；fact 只写随数据变化的事实（“共 45 人”）。

调用方提供：items（label、value、unit、delta、tone、help、fact）。

Table数据

表格：需要横向比较的数据（名单、成绩、商品）。放在内容板里，表头 surface-2 底、caption 字。

  • 第一列是主体（学生、任务），主名称用 body-strong，第二行用 small + ink-3 放元信息。
  • 每行只有一个视觉重点（分数、进度），数字列右对齐、等宽数字。
  • 列不超过 6–7 个；操作收进行尾的“…”，整行可点开详情。

调用方提供：columns（key、title、render、align、width）、rows、rowKey、empty。

EmptyState反馈

空状态：说清楚这里会出现什么、怎么开始，再给一个主操作。整页或整块没有数据时用；局部空（一个筛选没有结果）用一行灰字即可。

  • 标题说现状（“还没有任务”），说明说下一步（“下发第一个任务后，学生就能开始练习”）。
  • 插图是品牌色的几何块，不画人物、不用 emoji。

调用方提供：title、desc、action（通常是一个 primary 按钮）。
