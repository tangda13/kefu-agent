学生端改版：任务大厅 · 客服工作台 · 订单 · 评价 · 邮件 · 我的记录

学生端分两层：任务大厅、我的记录是“学习区”，可以直接说任务和成绩，版式和教师端一致（浅灰底 + 白色内容板 + 仪表盘卡片）；工作台、订单、评价、邮件是“店铺后台”，要像一套真实的跨境客服软件，内容区不出现“实训、任务、评分”。这次把两层的分工在侧栏里摆明，再逐页按“学生来这页最想知道什么、要做什么判断、做完去哪”重排，并把参数里学生端还没落地的 C1–C7、D1（限时、交互方式）和商品详情一起画进来。数据是编的（按 45 人班级、4 个任务），只看版式。

学习区回答“我现在该做什么、做得怎么样”首屏只放一个“现在要做的”任务，进度、截止、限时一眼看到；成绩用和教师端同一套仪表盘卡片，老师评语单独显示。
店铺后台回答“谁在等我、我手里有什么资料”工作台按“谁等得最久”排会话，顶部一条细栏放本班次剩余时间和接待进度；买家问到商品参数、物流、售后时，资料一点就开。
两层两种版式，颜色只给要处理的事学习区用浅灰底 + 限宽卡片（同教师端）；店铺后台四页左右顶格、白底铺满、不显示页名（侧栏选中项已经说明在哪），顶栏直接放页签或本场信息，像真实客服软件；老师的公告条只在学习区显示，店铺后台里收进铃铛。红：买家等太久、差评待回复、低于达标线；橙：快截止、快到时间。其他都是灰和墨色。侧栏只给“店铺后台”挂红色角标。

客服工作台 店铺后台

先讲依据：客户标签由谁打

查了千牛、飞鸽和海外常用的 Gorgias，三家做法一致：“这是哪类客户”由系统按会员和交易数据生成，客服只看不改；客服在接待时手动做的是记备注、标这次为什么来、标要不要跟进。所以参数里“按粉丝、大订单客户……等标签对买家进行标注”落成系统自动标注，之前稿子里让学生手动点选四个标签的做法作废。

平台系统生成的客户标签（客服只读）客服在工作台上手动做的
千牛（淘宝）聊天窗口右侧客户模块：官方云标签（红色）；会员等级来自店铺会员体系，没绑定会员的统一显示“店铺客户”；运营在“客户运营平台”按规则建的标签（蓝色）客户备注；长按会话加星标，标出重要客户；接待中心“任务”记下当场解决不了的问题
飞鸽（抖店）右侧工作台是订单、商品、快捷短语；客户分类在后台“客户管理”里由运营做备注、订单备注（右下角操作区）
Gorgias（海外）AI 识别来信意图和情绪，按规则自动加标签确认或修改 Contact Reason（咨询原因）：AI 先预填，客服单选；选项互不重叠，写买家能看到的原因（“发货延迟”，而不是“仓库出错”）
系统标签规则（RFM：最近一次购买 · 频次 · 金额）数据来源
粉丝关注店铺或是店铺会员画像客户价值层“粉丝客”
大订单客户单笔实付 ≥ USD 100，或近一年累计 ≥ USD 300（阈值可在店铺资料里改）这位买家的订单
沉睡客户最近一次下单超过 180 天画像“沉睡客” + 订单日期
普通客户有成交，不属于上面几类订单
新客还没有成交画像“潜在意向客”

一位买家可以同时有两个标签（如“粉丝 + 大订单客户”）。画像里的客户价值层（潜在意向客 / 复购老客 / 粉丝客 / 沉睡客，参数 1.4）是生成买家时用的设定；系统标签是按它生成的订单算出来给客服看的，和真实店铺一样。
对学生的训练点：看到标签就换话术（参数 1.4）；咨询原因练“听懂买家要什么”——AI 先猜一个，学生确认或改正，老师回放能看到改得对不对；待跟进和客户备注练“答应的事要落地”，同一位买家下次进线时，备注就在右栏。

现在“店铺”只是邮件页里写死的一个地址（support@auroramart-global.com），数据库里没有店铺。全平台只有一份商品库，老师在“场景配置 → 店铺商品”里维护，所以店铺资料也做成全平台一份，放在店铺商品页签的顶部，老师和管理员都能改（和商品同一套权限）。管理端“品牌设置”管的是平台名（外壳），店铺名是沉浸层里的模拟店，两者分开。
