# 总体开发架构

## 1. 架构结论

采用一个云端业务平台、两个 Windows 客户端、一个浏览器管理端：

```text
学生 Windows 客户端 ─┐
教师 Windows 客户端 ─┼─ HTTPS/WSS ─ 国内云 API 网关
浏览器管理端 ────────┘                 │
                                       ├─ 身份/RBAC/班级/任务/场景服务
                                       ├─ 会话编排与 LLM Provider 适配层
                                       ├─ ASR/TTS Provider 适配层
                                       ├─ 订单/邮件/考核/报表服务
                                       ├─ 监控、审计、指标与告警
                                       └─ PostgreSQL + Redis + 对象存储
```

Windows 客户端采用 Electron 外壳承载 React 界面，学生版和教师版分别构建、分别签名、分别发布。管理端复用同一套设计系统，但产物为浏览器 Web 应用。服务端采用 TypeScript/Fastify 的模块化单体起步，按业务边界组织模块；达到容量或团队拆分需求后再独立服务，避免初期分布式复杂度。

## 2. 仓库结构

```text
apps/
  portal/       角色隔离的 React 界面：student / teacher / admin
  desktop/      学生版、教师版 Electron 启动与打包配置
  api/          云端 API、SSE 流式对话、WebSocket 实训监控
packages/
  contracts/    跨端 DTO、枚举、校验模型和验收常量
  domain/       场景、画像、评分等纯领域规则与种子数据
docs/           产品基线、架构、路线图、需求追踪
```

## 3. 关键技术决策

### 3.1 身份与权限

- 登录成功返回短期访问令牌和可轮换刷新令牌。
- API 每个入口执行角色、班级和资源归属校验。
- 学生只能访问本人任务、会话、订单和记录；教师只能访问授权班级；管理员访问系统配置。
- 密码使用强哈希，重置生成一次性临时密码并强制首次修改。

### 3.2 AI 对话

- `ConversationProvider` 统一适配国产商业 LLM，可在管理端切换 Provider 和模型。
- 会话编排输入包括：场景约束、隐藏画像、订单状态、历史消息、教师介入信息和合规规则。
- 学生在开始前只能看到允许公开的买家信息，隐藏画像标签只在服务端保存。
- 服务端以 SSE 向客户端推送 token/文本增量，并记录接收时间、首字时间、结束时间、有效字符数与 Provider 调用信息。
- 生产环境在 Provider 未配置时拒绝开始 AI 会话；开发演示数据不能作为生产对话降级方案。

### 3.3 语音

- ASR/TTS 分别通过 Provider 适配层调用，至少配置 3 种语言。
- 音频先上传对象存储的短期私有地址，处理完成后按保留策略清理。
- 记录端到端耗时、Provider 耗时、语言、音频长度和错误码，用于 5 秒验收。

### 3.4 实时跟踪

- 学生端将轮次、计时、连接状态和得分事件写入服务端。
- 教师端通过 WebSocket 接收增量更新，并有 8 秒轮询兜底，满足不大于 10 秒刷新要求。
- 教师介入以带审计记录的系统消息进入同一会话事件流。

### 3.5 数据与备份

- PostgreSQL 保存账号、班级、任务、画像、订单、会话、评分与审计数据。
- Redis 保存会话游标、短期上下文、限流计数和实时监控状态。
- 对象存储保存语音、导出报表和备份文件，全部私有访问。
- 每日自动备份、定期恢复演练；管理端提供手动备份和备份结果查看。

## 4. 核心数据域

- IAM：用户、角色、教师授权、班级、学生分组。
- Training：任务、任务班级、业务环节、场景、交互模式、限时、状态。
- Persona：画像模板、随机规则、会话画像快照、公开/隐藏字段。
- Commerce：买家、商品、订单、物流节点、评价。
- Conversation：会话、参与者、消息、语音、教师介入、性能指标。
- Assessment：评分方案、维度权重、自动评分、人工复核、评语、能力雷达。
- Content：邮件模板、违规词、标准话术。
- Platform：Provider 配置、调用计量、告警、审计、备份、版本与运行状态。

## 5. 非功能设计

- 200 人规模按 100 个并发会话设计初始容量，所有 AI/语音外呼设置超时、重试、熔断和租户级限流。
- 对话性能日志直接生成 P50/P95/P99、首字达标率和平均输出速度验收报表。
- 关键操作、成绩复核、教师介入、Provider 配置和数据导出写入不可被普通用户修改的审计日志。
- 客户端启用上下文隔离、沙箱和受限 IPC；禁用渲染进程 Node.js 直接访问。
- API 密钥只保存在云端加密配置中，不下发客户端。
