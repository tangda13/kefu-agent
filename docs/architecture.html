1. 概览

交付形态
Windows 客户端（学生/教师）+ 云端管理端（浏览器）
规模与服务期
200 账号 · 3 年服务期
技术栈
React + Vite · Fastify + TypeScript · PostgreSQL 16 · Electron
AI 服务
LLM：经团队总网关 Flow API 调 DeepSeek，可多厂商切换 · 语音：豆包 TTS/ASR
代码仓库
github.com/tangda13/kefu-agent（main）
规模
32 张表 · 40 个迁移 · 约 150 个接口

三端共用一套 React 前端代码，按登录角色渲染不同导航；学生端/教师端是 Windows 客户端（Electron 外壳，页面从服务器加载，D-83），管理端在浏览器里打开同一地址。所有业务数据、AI 调用和密钥都在云端 API，客户端不持有任何密钥。

核心产品原则：实训是幕后逻辑。学生端的沉浸层（客服工作台、订单、评价、邮件）必须像真实的客服软件，不出现“实训、轮次、画像”等字样；任务大厅和我的记录属于学习管理层，可以直呼任务和成绩。

5. 核心业务链路

5.1 任务到会话

  1. 教师新建任务：班级、业务环节、场景、画像随机规则（persona_rule）、交互模式、限时、开放/截止时间、评分权重 → tasks + task_classes。
  2. 学生的任务进度 task_progress 置为待办；工作台把任务伪装成“未分配新客进线”。
  3. 学生接入：POST /v1/conversations 校验开放时间 → 按 persona_rule 从启用的画像模板中组合画像（domain composePersonaWithRule）→ 按场景生成订单、物流、评价（generateOrderForScenario）；售前场景没有订单，改为从在售商品里给买家挑一个“感兴趣的商品”写进画像快照。
  4. 买家主动开场：POST :id/opening（SSE），开场会引用订单号和物流状态。

5.2 一轮买家对话

  1. 学生发送消息（可连发；2 秒打字检测窗口结束后统一触发）→ POST :id/reply。
  2. 组装提示词（prompts/buyer.ts）：买家人设（每轮重注入防漂移）+ 场景剧本（目标、隐藏信息、情绪触发点、让步底线、结束条件）+ 订单或感兴趣商品（订单时间换成“Fri 9 Oct 2026 (4 days ago)”）+ 历史订单（buyer-orders.ts，学生在订单页看到的买家也知道）+ 时间锚点（prompts/time.ts：当前北京时间 + 本周 / 下周 / 下下周三周日历）+ 完整聊天（约 60000 字符预算，只防极端长会话）。买家是自主 agent（D-50）：开场拿到画像和剧本，之后只看聊天原文自己决定怎么接、何时离开；不再注入导演的情绪、阶段、备忘录和下一轮指令。客服发言满 25 轮时提示词加一句“这条收尾离开”（按规则触发）。两本账（D-90）：conversations.buyer_ledger 记这位买家来办的事（主要的 1 件 + 顺带 0–3 件 + 客服引出的最多 0–2 件，各自没办 / 办成 / 等客服回复 / 放弃）和还能忍几次（环节基数 × 耐心倍率，1–4），第一次轮到买家说话时由 domain 的 planBuyerLedger 定；提示词只给事实（清单进度、还能忍几次），按账该走了就写“这条收尾”。
  3. 漏中文兜底：买家回复（含催促）里出现汉字或中文全角标点（日语买家除外）时，按“话术与生成”用途改写成买家语言再落库，done 事件带 segments，前端在原位置换掉刚流出的气泡。
  4. 经模型网关按“买家对话”用途调用（gateway.stream("dialogue")），主档案出错且尚未出字时自动换备用档案；SSE 推给客户端；服务端解析 ||| 拆成 1–3 条短消息，识别 [END_OF_SERVICE] 结束标记。买家每条开头先写一段学生看不到的判断 <<reply=bad/vague done=2 wait=3 ask=1 leave=no>>（D-90，prompts/buyer-note.ts 流式截下、不外发，首字按第一个正文字算，约多 0.15 秒）；buyer-ledger.ts 的 settleBuyerTurn 记账并定这一条走不走（耐心用完、主要的事两次没答上 → 失望离开；没有还要问的事 → 收尾；该走没走 → 下一条一定收尾）；判断存在这一轮第一条消息的 buyer_note 上，下一轮原样放回聊天记录（不放回去买家第二条起就不写了）。默默离开的买家判断写 leave=silent：不落消息，之后学生再发也不调模型，巡检 2 分钟后按买家离开结束。
  5. 消息落库 conversation_messages；首字耗时（从服务端收到请求时算起）、输出速度落库 conversation_metrics（验收依据）；tokens 与费用落库 llm_usage。
  6. 异步：后台观察员（director.ts，原导演，D-50）按“满意度与表现评估”用途调用，看完整聊天（约 30000 字符预算），JSON 模式 + zod 校验（不合格带错误重试 1 次，仍失败保留上一轮状态），更新本轮得分、满意度、情绪、对话阶段 → conversations.state，给教师端走势、最终评分、催促快慢用，不回写买家。可设置每 N 轮学生发言运行一次以降本。
  7. 买家输出结束标记 → 服务端关闭会话 → 八项评分（assessment.ts，“能力评分”用途，D-46）：读全量对话（超过 24000 字符先分段摘要），把违规词命中、观察员逐轮得分、场景剧本、会话快照里的商品资料作为客观依据交给模型，模型打七项；消息响应时效由 @cecs/domain 的 computeResponsiveness 按消息时间计算（每轮从买家第一条消息算到客服第一条回复，首次响应 2 倍权重，买家等不到回复离开最高 40 分），不交给模型 → assessments（记录提示词版本、所用模型和依据）；任务成绩 = 该任务下所有已评会话的加权均分 → task_progress.score。自由练习会话不评分。
P2 已完成 Agent 底座（方案 J 节）：所有 LLM 调用经 llm/gateway.ts，按四种用途（买家对话 / 满意度与表现评估 / 能力评分 / 话术与生成）路由；提示词集中在 prompts/ 并带版本号；结构化输出统一 completeJson；场景剧本可由教师在「场景配置 → 场景库」编辑；Agent 评测集 dev.cmd eval。“自主买家 + 后台观察员 + 评分”三角色（D-50 起观察员只评估、不指挥买家），不引入编排框架；底层调用用 pi（@earendil-works/pi-ai 0.82.1）。

5.3 订单、邮件、评价中的 AI 辅助

订单页的催付、物流同步、差评回复，以及邮件页的 AI 辅助写信，都由“话术与生成”用途的模型实时生成三个版本（JSON 模式 + 校验），学生选择、二次编辑后发送到关联会话或邮件。邮件提交时服务端用 content_terms 词库复核违规用语；营销邮件按客户类型概率触发买家 AI 回信（mail_replies）。

5.4 教师监控与介入

实训跟踪页每 8 秒轮询 teacher/tracking（参数要求 ≤10 秒），买家消息超过 3 分钟未回会预警；教师可对任意会话发送指导，学生端通过 student/guidance 轮询，在顶栏铃铛里收到通知。

登录态：access token 为 HS256 JWT，有效期 15 分钟（ACCESS_TOKEN_TTL）；refresh token 14 天，数据库只存哈希，每次刷新轮换。密码用 scrypt 加盐。改密、重置、停用（学生和教师）时吊销该用户全部 refresh token。页签与账号角色不符时拒绝登录并提示。记住密码（D-51）：客户端登录页可勾选“记住密码”，账号和密码由 Electron 主进程用系统凭据（Windows DPAPI，safeStorage）加密后存本机 userData/remembered-login.json，渲染层不留明文；退出登录不清除，取消勾选立即删除。浏览器端不保存密码，交给浏览器自带的密码管理器。登录态本身存在 localStorage（cecs.session），关掉客户端再打开仍是已登录。前端续期：带登录的请求一律走 api/client.ts 的 authFetch，令牌以本机存的为准，401 时同一时刻只续一次再重发；刷新令牌失效或账号停用才回登录页。服务端续期宽限：续期换掉的刷新令牌记 rotated_at，60 秒内再拿来续期照样放行（续期响应丢了、两个页签同时续期时不掉登录）；登出、改密、重置密码、停用一律走 auth-context.revokeAllRefreshTokens（登出只清这个账号的宽限），宽限绕不过这些操作。

鉴权守卫：令牌只证明身份；每次请求再查一次账号状态和待改密标记（10 秒缓存，停用/改密/重置时立即失效）。停用的账号立即 401 ACCOUNT_DISABLED；待改密账号除改密和 /me 外一律 403 PASSWORD_CHANGE_REQUIRED。

登录限流：同一账号 15 分钟内连续输错 5 次锁 15 分钟；同一 IP 15 分钟内失败 100 次锁 15 分钟（机房共用出口 IP，阈值放宽）。返回 429 LOGIN_LOCKED，写审计 auth.locked。教师/管理员重置密码会解锁。部署在 nginx 后需 TRUST_PROXY=true，nginx 用 $remote_addr 覆盖 X-Forwarded-For。

找回密码：学生 → 教师重置；教师 → 管理员在「账号与权限」重置；管理员 → 服务器执行 pnpm reset-password admin（容器内 docker compose exec api pnpm reset-password admin）。
