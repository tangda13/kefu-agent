1. 概览

交付形态
Windows 客户端（学生/教师）+ 云端管理端（浏览器）
规模与服务期
200 账号 · 3 年服务期
技术栈
React + Vite · Fastify + TypeScript · PostgreSQL 16 · Electron
AI 服务
LLM：DeepSeek 默认，可多厂商切换 · 语音：豆包 TTS/ASR
代码仓库
github.com/tangda13/kefu-agent（main）
规模
28 张表 · 23 个迁移 · 约 80 个接口

三端共用一套 React 前端代码，按登录角色渲染不同导航；学生端/教师端由 Electron 打包为 Windows 安装包，管理端由云端 nginx 以网页形式提供。所有业务数据、AI 调用和密钥都在云端 API，客户端不持有任何密钥。

核心产品原则：实训是幕后逻辑。学生端的沉浸层（客服工作台、订单、评价、邮件）必须像真实的客服软件，不出现“实训、轮次、画像”等字样；任务大厅和我的记录属于学习管理层，可以直呼任务和成绩。

2. 部署拓扑（目标形态）

正式服务器待功能完成后购买（独立服务器、单独部署）。在此之前用本机或临时环境联调；客户端里的服务地址和更新源地址都做成可配置。

5. 核心业务链路

5.1 任务到会话

  1. 教师新建任务：班级、业务环节、场景、画像随机规则（persona_rule）、交互模式、限时、开放/截止时间、评分权重 → tasks + task_classes。
  2. 学生的任务进度 task_progress 置为待办；工作台把任务伪装成“未分配新客进线”。
  3. 学生接入：POST /v1/conversations 校验开放时间 → 按 persona_rule 从启用的画像模板中组合画像（domain composePersonaWithRule）→ 按场景生成订单、物流、评价（generateOrderForScenario）。
  4. 买家主动开场：POST :id/opening（SSE），开场会引用订单号和物流状态。

5.2 一轮买家对话

  1. 学生发送消息（可连发；2 秒打字检测窗口结束后统一触发）→ POST :id/reply。
  2. 组装提示词：买家人设（每轮重注入防漂移）+ 订单 + 场景 + 导演状态（情绪、阶段、记忆、下一轮指令）+ 最近历史。
  3. 调用 LLM 流式输出，SSE 推给客户端；服务端解析 ||| 拆成 1–3 条短消息，识别 [END_OF_SERVICE] 结束标记。
  4. 消息落库 conversation_messages；首字耗时、输出速度落库 conversation_metrics（验收依据）。
  5. 异步：导演 Agent（director.ts）再调一次 LLM，更新本轮得分、满意度、情绪、剧情阶段、事实记忆 → conversations.state，供教师实时监控和下一轮使用。
  6. 买家输出结束标记 → 服务端关闭会话 → 六维评分（assessment.ts）→ assessments；任务成绩 = 该任务下所有已评会话的加权均分 → task_progress.score。自由练习会话不评分。
规划 P2 期重构 Agent 底座（方案 J 节）：统一按用途路由的调用层、提示词模板化并带版本、结构化输出 + 校验重试、按轮/token 预算管理上下文、场景剧本化、导演降本、评分引入词库客观依据、Agent 评测集。保留“演员 + 导演 + 评分”三角色编排；底层 LLM 调用改用 pi（@earendil-works/pi-ai，锁 0.82.1，与 AIGC 平台共用）。

5.3 订单、邮件、评价中的 AI 辅助

订单页的催付、物流同步、差评回复，以及邮件页的 AI 辅助写信，都由 LLM 实时生成三个版本，学生选择、二次编辑后发送到关联会话或邮件。邮件提交时服务端用 content_terms 词库复核违规用语；营销邮件按客户类型概率触发买家 AI 回信（mail_replies）。

5.4 教师监控与介入

实训跟踪页每 8 秒轮询 teacher/tracking（参数要求 ≤10 秒），买家消息超过 3 分钟未回会预警；教师可对任意会话发送指导，学生端通过 student/guidance 轮询，在顶栏铃铛里收到通知。

7. 账号与权限

角色入口数据范围实现
学生客户端 · 学生登录页签仅本人数据所有学生接口查询都带 student_id = 本人
教师客户端 · 教师登录页签自己是班主任或被授权任课的班级teacherOwnsClass / scopedStudentsSql
管理员浏览器 · 管理端全部也可调用所有教师接口

登录态：access token 为 HS256 JWT，有效期 15 分钟（ACCESS_TOKEN_TTL）；refresh token 14 天，数据库只存哈希，每次刷新轮换。密码用 scrypt 加盐。改密、重置、停用（学生和教师）时吊销该用户全部 refresh token。页签与账号角色不符时拒绝登录并提示。

鉴权守卫：令牌只证明身份；每次请求再查一次账号状态和待改密标记（10 秒缓存，停用/改密/重置时立即失效）。停用的账号立即 401 ACCOUNT_DISABLED；待改密账号除改密和 /me 外一律 403 PASSWORD_CHANGE_REQUIRED。

登录限流：同一账号 15 分钟内连续输错 5 次锁 15 分钟；同一 IP 15 分钟内失败 100 次锁 15 分钟（机房共用出口 IP，阈值放宽）。返回 429 LOGIN_LOCKED，写审计 auth.locked。教师/管理员重置密码会解锁。部署在 nginx 后需 TRUST_PROXY=true，nginx 用 $remote_addr 覆盖 X-Forwarded-For。

找回密码：学生 → 教师重置；教师 → 管理员在「账号与权限」重置；管理员 → 服务器执行 pnpm reset-password admin（容器内 docker compose exec api pnpm reset-password admin）。
